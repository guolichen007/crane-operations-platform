# R7 模拟器发布、离线运输与运行身份登记操作手册

适用：`feature/crane-r7-sim-e2e` 及之后。数据库 Schema 12，不含迁移。本手册只用于**模拟（SIMULATION）/测试（TEST）运行身份**，不接真实行车，不涉及控制。

## 1. 发布工件

`dev/crane-*` tag 触发的 Dev Candidate 工作流在原有双镜像之后，**另外**构建：

| 工件 | 来源 | 清单 |
|---|---|---|
| `ghcr.io/guolichen007/crane-operations-platform/dev/device-simulator:<SHA>` | `deploy/Dockerfile.backend`，`TARGET=simulators/device-simulator`，`SOURCE_SHA` 标签 | `simulator-manifest.json`（kind `crane-dev-simulator`：digest、platform、SBOM 哈希、CI/Candidate run id） |
| `*.cdx.json`、`*.trivy.json` | 与双镜像同一扫描链（Trivy HIGH/CRITICAL 为 0 才推送） | artifact `crane-dev-candidate-<SHA>` |

`dev-manifest.json` 结构不变，仍只有 cloud-api 与 web-console 两项；`release-check.mjs` 仍要求恰好两项。模拟器从不出现在生产双镜像清单中，生产 compose 只能通过 `docker-compose.prod.simulation.yml` 的 `simulation` profile 显式启用。

## 2. 离线运输（按原始 digest）

不要用 `docker save`：它会重新打包层并丢失 registry manifest，导致按 `@sha256` 引用时找不到镜像（GHCR 压缩层缺失问题的来源）。

```bash
set -euo pipefail; umask 077
# 联网的受控机器（需要 skopeo）：
node tools/oci-transport.mjs pack release/dev-candidate/dev-manifest.json       r7-transport/main
node tools/oci-transport.mjs pack release/dev-candidate/simulator-manifest.json r7-transport/sim
# 产出：<name>.oci.tar、<name>.oci.tar.sha256、transport.json（digest、平台、字节数、归档 sha256）

# 目标主机（离线）：
node tools/oci-transport.mjs verify r7-transport/main
node tools/oci-transport.mjs verify r7-transport/sim
```

`pack` 用 `skopeo copy --all --preserve-digests`；先核对 registry 原始 manifest 字节的 sha256 等于 digest，再核对归档内 manifest 仍等于该 digest。`verify` 离线检查归档 sha256、manifest digest、`org.opencontainers.image.revision` 标签等于源 SHA，并打印平台（预期 `linux/amd64`）。

导入到目标主机后按 digest 解析：用本机回环的临时 registry `skopeo copy --preserve-digests oci-archive:… docker://127.0.0.1:5000/…`，再按同一 digest 拉取；`docker image inspect <ref@sha256>` 的 revision 必须等于源 SHA。此导入路径首次使用前只做导入与核对，不启动服务。

## 3. 运行身份登记（runtime-identity）

已有的 startup Inventory 导入**不得**用于在线新增运行身份：它会静默创建缺失的项目和资产、删除旧 `Project-A` 种子、不看资产状态、不写审计。改用 cloud-api 镜像中的 `runtime-identity`：

```json
{ "tenantId": "demo",
  "entries": [
    { "runtimeDeviceId": "SIM-UAT-0001", "projectId": "<已存在的测试项目>", "assetDeviceId": "<该项目已存在的资产>",
      "sourceMode": "SIMULATION", "equipmentInstallationId": "<可选：该资产上在用的 Equipment>" } ] }
```

```bash
TOOL=(docker compose … run --rm --no-deps --entrypoint runtime-identity \
  -e DATABASE_URL='postgres://crane_app@postgres:5432/crane_app?sslmode=disable' \
  -e DATABASE_PASSWORD_FILE=/run/secrets/app_db_password -v "$PWD/req.json:/req.json:ro" cloud-api)
"${TOOL[@]}" plan   --request /req.json > plan.json      # 只读；target 必须是 crane_app/crane_app/12
"${TOOL[@]}" apply  --request /req.json --approve "$(jq -r .plan.digest plan.json)" --actor <管理员> > apply.json
"${TOOL[@]}" verify --request /req.json                  # 退出 0 = 全部按请求登记
"${TOOL[@]}" fleet  --request /req.json > fleet.json      # 生成 Fleet（ACL/证书/模拟器 --fleet-file 的输入）
```

规则：只接受 `SIMULATION`（`SIM-` 前缀）或 `TEST`（`TEST-` 前缀），`REAL` 一律拒绝；项目与资产必须已存在且同项目、同租户，资产不得为 RETIRED；已有身份的项目/资产/来源不可变（SIM 永远不能改成 REAL）；一个资产每种来源最多一个运行身份；Equipment 绑定必须是该资产上未拆卸、未被绑定的安装。apply 与 Inventory 导入同一把咨询锁、单事务，digest 包含目标库身份且只能成功使用一次，每个新身份、每个绑定各写一条审计，绑定另写 `entity_revisions`。

随后：`go run ./tools/fleet --fleet-file fleet.json --out <acl>` 生成 Mosquitto ACL；`go run ./tools/certs --fleet-file fleet.json --out <dir>` 为每个身份签发设备证书（开发 CA，仅隔离测试使用）。cloud-api 以 `FLEET_FILE` 启动时会用 `device.ValidateFleet` 再次核对 Fleet 与数据库一致。

## 4. 场景与测试命令

| 场景 | 含义 |
|---|---|
| normal | BIRTH、15 分钟心跳、1 小时快照；WATCH 时 1 Hz LIVE |
| intermittent | 每 20 秒进程级重启（新 bootSeq），间隔 5 秒 |
| alarm-storm | 每 2 秒一条 ALARM，进入关键事件 spool，收到 EVENT_STORED_ACK 才出队 |
| offline | 不连接（用于"注册但离线"反证） |

```bash
# CI（integration 作业内，固定 Mosquitto/PostgreSQL 镜像）：
node tools/r7-sim-e2e.mjs
# 60 分钟 20 台：GitHub Actions → Crane R7 SIM Soak → minutes=60（只读、不部署）
```
