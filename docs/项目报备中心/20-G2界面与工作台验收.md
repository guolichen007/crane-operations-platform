## 2. 关键决策

**候选规则修订（负责人批准）。** 00004 迁移后历史项目全部 INCOMPLETE，原实现要求每个重复候选也有 COMPLETE 提交快照，导致与历史项目相似的新报备只能退回。现主项目仍须本轮证据完整且审核人独立；候选只要求可读且审核人从未是其创建人、负责人、提交人、快照参与人、参与记录 actor/owner 或归属历史操作人。15 号 ADR 已同步修订。

**一处定义，三处使用。** `review_eligibility.go` 的 SQL 片段同时用于审核 POST 事务、详情/列表 `review` 提示与首页 `reviewable` 计数，测试逐项比对三者一致。

**管理员批量交接。** `transferStaffProjects` 允许 `adminRole`，但 `manager()` 语义不变；读取范围仍由 `projectScopeAt` 决定，沿用身份排它锁、逐项版本、归属历史、审计与 ASSIGN 参与证据，交接人此后不能审核该项目。

**创建回执。** `GET /api/v1/project-create-receipts/{key}` 仅对当前有效会话的原 actor、且仍有读取权时返回当前版本；其他账号、失去范围或不存在一律 404。前端在 sessionStorage 按账号保存意图键与“已发送”标记，保存或刷新前先查回执，找回后改为 PATCH。
