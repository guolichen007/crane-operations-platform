# 生产安全与限流契约

本轮仅本地验证模板，未部署生产、未创建账号/Client/网络或签发证书。

OIDC 仅接受 resource_access.baobei-web.roles 与数据库 app_users 有效角色交集。Realm Role 和其他 Client 不授权。回调 state_hash/binding_hash 摘要落库；nonce/PKCE verifier 仅服务端数据库，TTL 5分钟，DELETE RETURNING 原子消费。全局 pending 上限1024，容量检查由数据库 advisory lock 串行；每分钟清理过期 pending/session，并在创建登录时清理 pending。Session 8小时不滑动，Cookie __Host-baobei_session Secure/HttpOnly/Lax/Path=/，无 Domain；Mutation 同源 Origin + CSRF。

## IP 信任链与限流
shared ingress → u-dao-baobei-frontend → baobei-web → baobei-api。API 不读取或信任 X-Forwarded-For/X-Real-IP 进行身份或 per-IP 限流。内层 web 清空这些头，避免引入可伪造地址的授权漏洞。

外层 shared ingress 由服务器任务线基于真实连接来源及明确受信代理 CIDR 配置 real_ip；禁止 0.0.0.0/0，禁止把任意客户端提供的 XFF 直接作为真实IP。外层覆盖而非盲目透传客户端代理链。
建议外层在确认真实IP链后：/auth/login 每IP 6次/分钟 burst=5；/auth/callback 每IP 20次/分钟 burst=10，超限429；共享NAT/大团队登录容量应先观测并由负责人调整。不得在本轮实际修改 ingress。

内层生产模板按 server_name 做全局桶，login 10r/s burst20、callback 20r/s burst40；不把 ingress 的固定地址误称为真实用户IP。应用1024 pending容量提供跨实例最终保护。记录限流计数即可，不记录query/code/token/cookie/body。官方机制：https://nginx.org/en/docs/http/ngx_http_limit_req_module.html 。

## 生产拓扑与秘密
compose.production.yaml 使用三个独立容器，端口发布全部为空。web 仅 frontend/internal，API 仅 internal/egress，DB 仅 internal；internal=true。frontend 为由 shared ingress 任务线准备的独立 external 网络，禁止加入 crane/firebot/通用ingress网络。API独占egress以访问指定企业issuer。
只有shared ingress 应接入 frontend；Docker主机管理员须控制此网络成员，Compose静态配置本身不能阻止主机管理员额外连接容器。egress 非防火墙目的地址白名单；目标域名只读配置，部署任务线如需出口ACL另行审查。

OIDC_CLIENT_SECRET_FILE、DATABASE_URL_FILE、POSTGRES_PASSWORD_FILE 从外部目录注入；Git 仅保存文件路径契约，无秘密示例值。生产配置Gate：APP_ENV=production，DEV_AUTH=0，origin/issuer/client精确匹配。数据库用户与权限、备份目录权限、密码轮转由服务器任务线负责。
Nginx 使用 Docker DNS resolver 127.0.0.11 与变量 proxy_pass，每10秒重解析，无固定容器IP。/auth（尤其callback）access log关闭；error log仅crit。所有生产模板通过 config/隔离反证与 nginx -t；不在本轮启动真实生产模板。
