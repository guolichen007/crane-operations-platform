# UI 设计规范与交互动作矩阵（G0）

状态：可验收交互设计，未实现。以 `8221cdab7bc6017aa0936f866478bdb607eb9f02` 的 Vue/Router/Pinia、ActionButton、Modal 和原动作矩阵为现状。目标角色和资源判断以 [权限 ADR](15-业务权限与审批自审ADR.md) 为准，页面不自行发明角色权限。

## 1. 页面及导航收口

| 路由 | 现状 | 目标/角色 |
| --- | --- | --- |
| `/` | Dashboard 通用卡片；admin 侧栏无此入口 | 四角色专属任务顺序、真实 scope/统计；保留 staff-role-draft 回跳优先级 |
| `/projects` | 我的报备，共用列表 | 我的/团队/全部项目，按服务端 scope 命名；admin 未分配入口 |
| `/followups` | Projects，共用 due=true | 逾期与未来七日独立筛选；sales 本人，其他管理范围 |
| `/pipeline` | 当前页分栏 | 后端阶段总量+每栏独立分页，明确已加载 N/共 M |
| `/statistics` | 复用 Dashboard | 独立分析页，范围/时间/口径/更新时间，无数据也有说明 |
| `/new` | 仅 sales，三步 | sales/admin 渐进创建；新建按钮和零数据 CTA 同一能力来源 |
| `/projects/:id/edit` | 仅 sales 路由 guard | Project.actions.edit 及 D/R，admin 有合法编辑权；服务端复核 |
| `/projects/:id` | 详情、跟进/治理 Modal | 六标签详情、资源动作、可审/不可审原因、真实归属 |
| `/reviews`、`/duplicates` | manager/director | admin 独立审核；只显示有范围权限的待审，冲突仍受控禁用 |
| `/settings/users`、`/settings/teams` | admin 组织管理 | 原近期认证/同步/激活与错误恢复流程完整保留 |
| `/team/members`、`/team/members/:id` | manager/director/admin 人员治理 | 保持现有 scope 和回跳；不把业务全局读权赋给整个 staff 页面 |
| `/login` | 企业登录、固定错误恢复、开发显式入口 | 保留生产无开发提示、401 与网络/503 区分；不新增密码系统 |

“待我处理”本期作为工作台可链接过滤区，复用 reviews/followups/未分配列表，不再建没有接口的门户。“异常与审核历史”通过详情审计和受控过滤进入，不建立假的独立事件流。导航分组按 PRD，移动端可折叠；sales 不显示无权限的组织菜单。

## 2. 页面线框与逐页验收

以下线框仅表示信息层级，均为设计，不能当成本次浏览器截图。

```text
桌面公共壳（1440/1366）
┌ 侧栏 248px ┬ 搜索［项目/客户/编号］   ［新建］ 范围/角色  账号 ┐
│工作空间    │ 标题 + 任务说明 + 统计时间/筛选                     │

```

### 四角色首页

```text
Sales：［快速报备］［续填草稿］［记录跟进］
       逾期待办 | 待补资料 | 待审核 | 未来七日 → 最近项目/真实活动
Admin：［新建项目］［待分配 N］［独立可审 N］［管理人员］
       全局业务概览 → 未分配/等待独立审核 → 同步失败/待激活 → 最近操作
Manager：［本组可审 N］［重复处理］［待交接］
         团队逾期 → 销售负载 → 本组项目趋势
Director：［跨组重复］［关键风险］［授权全局管道］
          阶段分布 → 团队比较 → 保护/逾期风险
```

首页每项数量链接到同 scope、同筛选的真实列表。没有独立审核人时显示“等待独立审核人”，可审数为 0，不能伪造可点击任务。admin 没有有效销售时同时提供“先建立草稿”“邀请销售”，指派框显示空态而不是假销售。每角色有数据/零数据都需在 G4 留四屏宽证据。

### 新建/续填

```text
快速草稿 → 设备与技术 → 商务与下一步 → 核对提交
客户［可未知］ 项目名［可未知］ 省市［可未知］ 来源［可后补］
管理员：归属［待分配 / 指派有效销售］   销售：归属［本人，只读］
保存状态：有改动 / 保存中 / 已保存(时间) / 失败(保留输入+重试)
底部：［保存草稿］［下一步］；核对页：［提交正式报备］+缺项清单
```

草稿允许缺失，正式必填按当前后端必填（客户/项目/省市/类型/主要需求/需求分类/来源/可信度）与合法归属；设备未知不填假零。查重条件不足显示“信息不足，提交前需核验”，不能显示绿色“无重复”。候选仅显示授权脱敏信息；正式提交再次查重，以响应状态显示进入审核。

创建幂等键在同标签页一次创建意图内复用；得到 id 后改为 version PATCH。点击/自动保存排队串行，防止创建响应丢失重复项目。409 停自动保存，保留用户输入，提供重载并对照，不静默覆盖；网络/503 显示可重试，失败不清表单。离开、刷新、后退沿用未保存确认；跨刷新恢复只承诺已成功落库草稿，不把内存表单说成持久恢复。若未来增加本地缓存须另审敏感数据保留和账号隔离。

### 列表、管道和详情

```text
列表：范围［全部/团队/我的］ 当前筛选总计 N · 当前页 M
      关键词/城市/状态/阶段/负责人/日期 → 表格/移动卡片 → 稳定分页
管道：每栏 标题/真实总量/已加载 → 卡片 → 本栏加载更多
详情：标题/编号/客户/位置 负责人(未分配) 状态/阶段 ［允许的动作］
      概要 | 设备与技术 | 跟进时间线 | 审批与重复 | 归属记录 | 操作审计
```

详情保留单位、未知项、真实 actor、原 creator 和当时归属；不把 sub 当显示姓名，不因 null 显示某个人。姓名缺失用“姓名待核对”，必要技术标识放在受控运维视图。审核区说明可审原因或“参与此项目/历史证据待核验”，不泄露其他主体私密详情；输入原因、版本确认后提交，成功刷新同一项目、队列及计数。

## 3. 目标动作矩阵

下面是 G1–G4 的目标动作，不添加到现有 77 个已绑定动作统计；已有 ActionButton action-id 尽量复用，新增 ID 随实现批次进入原矩阵与自动校验。所有写操作在 API 成功后才显示成功；加载时禁重入，失败保留表单和焦点。

| 动作（复用/拟议） | 角色/状态 | 依赖 | 确认与成功证据 | 失败/禁用 |
| --- | --- | --- | --- | --- |
| nav.open/global.search | 全部有效角色/授权范围 | `/me`、GET projects | 导航/提交搜索；URL 带筛选 | 401 登录恢复；503 原页重试，不冒充无数据 |
| project.create | sales+create/admin | POST projects；幂等键 | 返回真实 id/编号；只称保存草稿 | 禁用原因；超时复用键，不能造第二条 |
| draft.save（目标复用现有保存动作） | sales owner/admin，D/R/∅ | POST 或 PATCH+version | aria-live 持续保存状态、服务器时间 | 409 停保存并对照；503/断网保留 |
| project.submit | sales+submit/admin，已分配 D/R | POST submit+version | 核对页确认，响应 SUBMITTED/UNDER_REVIEW | 缺失项/owner 停用/裁决/证据说明 |
| duplicate.check（输入行为） | sales/admin，编辑可见项目 | POST duplicate-checks | debounce、过期响应丢弃、提交时重算 | 不足信息/网络失败都不等于无重复 |
| ownership.transfer | manager/director/admin，合法状态 | GET candidates、POST ownership-transfer | 原/新负责人、原因、版本二次确认 | 目标失效/409 重载，不清原因 |
| activity.open/create | sales owner+activity/admin，Q/A | POST activities+version | Dialog，真实跟进事件+版本 | 校验错误/503 保留；D/R/T 有原因禁用 |
| project.stage-change | sales owner/admin，D/R/Q/A | POST stage-change+version | 当前/目标阶段+原因 | 非法跃迁/终态拒绝 |
| review.open | manager/director/admin，范围内 Q | GET comparison/detail | 先加载当前证据/可审原因 | 无范围404；冲突可读不可写 |
| review.approve/return/reject | 独立审核人，Q | 对应 POST+version | 理由+当前版本确认，审批事件 | REVIEW_CONFLICT/EVIDENCE、409/503 |
| duplicate.confirm/dismiss | 全部关联范围且独立，Q | POST duplicate-decisions | 明确“拒绝此报备”/“全部排除并批准”影响 | 候选受限/不完整拒绝；不可只审一个后默认全部 |
| project.preview/detail | 授权资源 | GET detail | Sheet/六标签，焦点返回 | 404/503 区分，不能仅靠旧缓存显示成功 |
| project.page-prev/next | 列表 | GET projects | 页数/总量/加载数清楚 | 边界禁用说明 |
| pipeline.load-more（拟议） | 各角色 scope | stage-summary+stage 列表 | 每栏分页，不影响其他栏 | 本栏错误重试，已载卡片保留 |
| statistics.filter（拟议） | 各角色 scope | summary/stage-summary | 口径/时间更新，已知金额/未知数分开 | 过滤错误400；无数据与故障不同 |
| staff.role-reauth/promote 等 | 原 admin 近期认证流程 | 原 auth/staff 端点 | 原标签页草稿、本人/员工/version/五分钟、显式确认 | actor/version 不符丢弃草稿；同步失败不激活 |
| auth.login/retry/logout | 有效会话/恢复页 | 原认证端点 | 固定中文错误与企业登录 | 无原始 OIDC/JWT/技术堆栈、生产无开发入口 |
| guard.stay/leave、dialog.cancel | 有未保存输入 | 本地确认 | 明确放弃才离开，焦点恢复 | 取消保留输入及保存状态 |

## 4. 视觉、响应与可访问性

沿用 Vue3/Pinia/Router、reka-ui 2.6.x、Lucide。明亮中性色、深蓝主色、有限风险强调色；不添加大 UI 框架、不复制第三方皮肤。正文建议 16px、次级 14px、少量标签 >=12px；侧栏 240–260px、顶栏 64–72px，信息密集区仍有清楚行距和层级。

| 宽度 | 布局验收 |
| --- | --- |
| 1440×900 | 固定侧栏、任务与概览分区、完整表格；无需横向滚动看主要动作 |
| 1366×768 | 减少首页并列卡片，主要 CTA 和待办首屏可见 |
| 768px | 折叠导航、两列转一列、详情标签可滚动且有名称 |
| 390×844 | 单列卡片、44px 触达、固定底部主操作不遮输入；键盘弹出仍能保存 |

支持 Tab/Enter/Space、可见焦点、Dialog 焦点陷阱/Esc/返回原按钮；loading 用 aria-busy，保存状态 aria-live；不能只靠颜色区分状态。每页覆盖 loading/empty/无匹配/成功/保存失败/401/403/404/409/503/待激活；Toast 只补充回执，不能替代稳定保存与字段错误。未授权入口隐藏；已授权但条件不满足的动作显示禁用原因；直接改 URL 仍由服务器判定。

## 5. G0 与后续证据边界

本批仅线框与动作规格，`UI_SCREENSHOTS=NONE`。G2–G4 必须使用真实浏览器、临时签名 OIDC、真实 PG 和生产模式隔离环境，证明请求、DB、页面结果对应；截图不能替代点击/网络与事务断言。四角色四屏宽有数据/零数据共至少 32 组首页证据，另覆盖列表、创建、审核、详情和所有主动作。截图/trace 只放忽略的 local-private，不含真实员工、客户或凭据。
