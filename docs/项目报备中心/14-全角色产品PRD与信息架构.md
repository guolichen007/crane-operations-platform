## 1. 本次产品裁决及适用顺序

Baobei 是非标自动化行车/起重设备项目报备与销售跟进产品。四个角色都有可完成任务的工作台；admin 管理 Baobei 全部合法业务项目，可在没有有效销售时先建真实未分配草稿，再指派、提交和代录跟进；仅可独立审核自己未参与且证据完整的项目。

本裁决替代旧版“admin 只管组织、不管理业务项目”的产品限制。`01-架构.md`、`02-数据模型.md`、旧交互矩阵和 BB-B1/B2/B3 报告保留为已实现版本的历史证据，不能据本 PRD 宣称现有按钮或 API 已开放。旧《销售采集优化 PRD R0》若另行提供，其冲突条款也以本裁决为目标；该文件不在本次产品目录盘点中，未假定已审阅其全文。

目标优先级：本 PRD 定义业务边界；[权限 ADR](15-业务权限与审批自审ADR.md) 定义资源与独立性；[数据库 ADR](16-待分配草稿与数据库迁移ADR.md) 定义持久化、兼容与并发；[UI 规范](17-UI设计规范与交互动作矩阵.md) 定义页面行为；[风险矩阵](18-测试追溯矩阵与部署风险.md) 定义验收与发布阻断。发生冲突应先修订设计，不由 UI 猜测权限。

## 5. 主流程及可验收结果

### 5.1 速记草稿到正式报备

速记首屏只集中客户、项目名、省市、来源，允许未知和缺失。至少发生一项有意义输入才触发自动创建，避免进入页面就生成空项目；用户显式“保存草稿”可保存未命名草稿。60–120 秒是后续真实浏览器计时验收目标，本批未实测。

后续分组：设备与技术（桥式/门式/其他、多台设备、数量、载荷 t、跨度 m、起升高度 m、环境与自动化需求）；商务与下一步（可信度、改造/扩建/新建、采购日期、已知金额、下一动作/日期）；核对提交（缺失项、最新查重、归属、独立审核条件）。未知数值为 null，不能用 0 代替；旧数值解释见数据库 ADR。

销售归属由当前有效身份与真实团队确定，不接受请求的 creator/team/owner。admin 选择“待分配”或有效 sales；没有有效目标也可保存。未分配仅 admin 可见；指派后按 owner/team 公开。提交要求有效 owner、有效团队、完整正式字段、当前 version，以及事务内重新查重。成功文案分别为“草稿已保存”“已提交，等待审核/重复处理”；保存从不被称为正式报备。

普通相似候选生成 UNDER_REVIEW 队列；与既有流程一致，疑似重复不会自动成为第二条已批准归属。已确认的强重复不得靠重新提交清除：保留裁决证据并阻止正式生效，只有独立审查确认 DISTINCT 的当前版本才可批准。无独立审核人不阻止合法保存和提交，队列显示等待原因，不自动批准。

### 5.2 指派、编辑、跟进与审核

指派/转移复用既有 ownership-transfer；目标必须是当前有效 sales 且具有有效团队，操作必须有原因和版本。creator 永不随转移变化；操作人、前后归属、当时团队及参与证据同事务落库。manager 限本组，director 按原全局，admin 可跨组。人员批量交接也必须沿用同一业务证据规则。

草稿/退回可编辑和提交；提交后不修改采集正文，先独立退回再补充。跟进限 SUBMITTED/UNDER_REVIEW/APPROVED，sales 仍需 activity 能力，admin 代录保留真实 actor。普通跟进不冒充创建或提交，但实质更改审核依据/归属会扩大反自审冲突集合。manager/director 本期不代写销售正文或跟进。销售阶段按既有逐步前进、暂停/结束原因约束，admin 代录阶段同样审计，不混用报备状态。

审核通过、退回、拒绝及“排除重复并批准”共用独立性策略。无权限不读取正文；有读取但有利益冲突时显示不可审原因。历史独立性不完整的待审记录 fail closed，保持原状态，后续核验方案未通过前禁止批准。

## 6. 数据与统计口径

列表显示服务端筛选 total、当前页 items 数及范围标签。共同过滤为关键词、状态、阶段、省/市、负责人、团队（依权限）、更新时间窗、跟进时间窗、待分配；排序必须稳定，page/pageSize 上限沿用 100。未知过滤参数/格式在目标契约返回 400，现状不能误写为已支持。

所有聚合使用同一资源 scope 与过滤结构；一次聚合在同一数据库快照/单 SQL 内计算，返回 `asOf` 和规范化 filters。独立请求之间的并发变化允许导致轻微差异，页面按 asOf 说明并整体刷新，不能声称跨请求强一致快照。

有效报备为 SUBMITTED/UNDER_REVIEW/APPROVED，三种单独计数；草稿、退回、待分配分别计数。逾期为 `nextFollowupAt < asOf`；未来七日为 `[asOf, asOf+7天)`，与逾期不重叠，时间边界为 UTC，页面按 Asia/Shanghai 展示。审核“队列数”和“当前人可审数”分开；保护风险按 protectionStatus，绝不混同 intake EXPIRED。阶段汇总覆盖全部 12 阶段并在同一筛选下计数，金额返回已知金额和未知数量，0 是已知金额，不做伪造总额/排名。
