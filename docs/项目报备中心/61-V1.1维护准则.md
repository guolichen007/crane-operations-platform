# 61 · Baobei V1.1 维护准则

适用于 V1.1.0 投产之后的生产维护模式（功能冻结、研发关闭）。

## 1. 缺陷处理流程

```
登记 → 复现 → 根因 → 最小修复 → 自动回归 → OWNER 批准推送 → CI → 服务器部署 → 现场验证
```

| 步骤 | 要求 |
|---|---|
| 登记 | 写明现象、影响范围、发生时间、角色和页面；不附手机号、密码或截图原件 |
| 复现 | 优先在本地或 CI 的合成数据上复现；需要服务器信息时，由服务器 CC 只读提供脱敏证据 |
| 根因 | 指出代码、配置或数据层面的确切原因；查不清时只记录现象，不做猜测性修改 |
| 最小修复 | 只改与根因相关的代码；不顺带重构，不扩展功能；新迁移从 00017 开始，00001–00016 不改 |
| 自动回归 | 修复处补测试，并跑相关的 contract、lint、test、e2e；没跑的写 NOT_RUN |
| 推送 | 助手只准备本地提交草案；由 OWNER 批准并执行推送 |
| CI | 同一 SHA、同一 Run、Attempt 1、8/8 |
| 部署 | 服务器 CC 按书面说明执行：构建、扫描（0 CRITICAL / 0 HIGH）、同 Schema 走普通 up，Schema 变化走维护窗口 |
| 现场验证 | 只验证这次修复及受影响的链路，结果写入补丁说明 |

## 2. 版本与 Tag

- 已发布的 Tag（`baobei-v1.1.0` 及以前）**不可覆盖、不可移动**，已发布的 Release 不修改。
- 下一次必要补丁为 **`baobei-v1.1.1`**：附注 Tag 指向现场验收通过的运行 SHA，由 OWNER 执行。
- **安全补丁与功能迭代分开提交、分开发布**：安全补丁不夹带功能改动。
