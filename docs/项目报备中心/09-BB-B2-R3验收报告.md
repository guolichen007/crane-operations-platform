# BB-B2-R3 无重建 Ingress 的 HTTP-01 验收

启动基线为 `0f153931e18d37eb73b752b8a86bfd3498e01023`。本地与远端均为 `product/baobei-v1` 的该提交，工作区干净。基线 CI Run 41764142151 八门通过。

Baobei common 仅保留两个限流区，HTTP 和 HTTPS vhost 各自声明 resolver 和超时。HTTP challenge 代理到 `baobei-web:8080`，保留路径和查询串，其余 HTTP 返回 HTTPS 308。Web 只读绑定宿主 webroot，只服务单段 token 的 GET/HEAD，禁缓存、目录列表和符号链接。TLS 私钥留在共享入口的原 TLS 根挂载内。

## 验收证据

本地复验入口为 `node tools/task.mjs baobei http01-test`。先执行同一入口的 `compose`、`up` 和 `cert-test`，准备 Nginx、开发镜像和隔离测试工具镜像。新 fixture 自建后端网络和数据容器，使用独立的临时文件。

| 验证 | 本地结果 |
| --- | --- |
| Resolver | Nginx 1.30.4 独立解析和组合 Firebot 风格全局 resolver 均通过。恢复重复全局 resolver 后解析失败 |
| 原容器 reload | 共享 Nginx 先服务模拟 Firebot，经原配置目录引入 Baobei 并 reload。容器 ID、启动时间、配置根和 TLS 根挂载一致，原模拟站点仍返回 204 |
| HTTP-01 | IPv4 隔离 Docker 网络内，模拟 ACME 在启动后写入 token，Web worker 从只读 bind 读取，公网入口形态返回原响应体。缺失 token 返回 404，普通 HTTP 路径与无斜线 challenge 前缀返回 308 |
| HTTP-01 反证 | Web root 用户写入也被只读挂载拒绝。目录、URI 越界和符号链接无法返回文件。非 GET/HEAD 返回 405，正常响应带 no-store |
| 服务回归 | 同一 TLS 入口代理真实 Baobei API 和临时 PostgreSQL，/api/、/auth/、/health/、SPA fallback 通过。所有 fixture 容器无 host port，API 和数据库只接后端网络 |
| 生产 Compose | 三服务拓扑、Web 单独只读挂载、Web 无 TLS 私钥挂载及 host port 反证通过 |
| 证书生命周期 | 原 34/34 通过，含固定版本、SAN/Key/Chain、事务推广与恢复、SIGKILL、Critical Latch 和回退 |
| E2E 与恢复 | Chrome 桌面和移动 18/18，备份恢复验证 23 张表和关键关系通过 |
| 契约与构建 | 原 51 个 action bindings、17 组生产静态反证、Go/Vite lint、单元、原 5 组发布合成测试与本地镜像构建通过 |
| 安全 | npm/Go 漏洞和 gitleaks 扫描通过 |
| GitHub CI | 同一提交八门结果以任务最终报告的运行链接为准 |

Docker Desktop 初次为测试网络自动启用了 IPv6，HTTP 请求命中镜像自带的 IPv6 默认站点。fixture 显式限定 IPv4 并以已有配置目录模拟共享入口，生产 vhost 的监听族保持原契约。Firebot 配置仅复现已知的全局 resolver 作用域。本轮验证使用合成 TLS、Docker DNS 和本地容器。实际公网 HTTP-01 可达性须在后续授权部署中核对。

首轮远端 Compose 在原 34 项证书测试通过后发现跨版本 JSON 差异。部分 Compose 版本将 `create_host_path: false` 省略为 `bind: {}`。门禁同时检查源 YAML 显式禁止自动建目录、两种渲染形式及 `true` 反证。
