## 1. 产品范围（冻结）

- **项目报备**：销售/主管本人报备；重复识别；保护期。
- **审核**：主管审核销售报备，总监审核主管本人报备；审批记录不可改写。
- **项目中心**：六组 12 码销售阶段、管道视图、深滚动返回位置。
- **跟进中心**：逾期/今日/本周/未排期，北京时间。
- **客户中心**：团队客户档案与联系人。
- **技术需求**：技术简报、修订记录与澄清问答。
- **数据分析**：本人/团队/成员/全部，分层统计。
- **人员与账号**：管理员在网页完成成员、团队、开户、重置密码、换手机号、停用/恢复、改角色、调组、异常核对；首次认领（V1.1 投产新增）。

V1.1 之后不再扩展销售业务功能，只修缺陷与日常运维。

## 2. 投产新增（本次提交）

1. **首次认领**（迁移 `00016_account_claim.sql`）：
   - 管理员可以给成员发放唯一的**临时登录名**（如 `sales01`）和一次性临时密码，这时不需要手机号。
   - 首次登录时成员必须完成：Keycloak 强制改密 → 填写真实姓名 → 填写本人手机号（格式和唯一性都会校验）。
   - 提交后，Keycloak 用户名改为该手机号（同一 UUID），临时登录名随即失效，所有会话结束，成员需用手机号重新登录。
   - 认领完成之前，后端只放行 `GET /api/v1/me` 和 `POST /api/v1/me/claim`，其余业务接口一律返回 `403 ACCOUNT_CLAIM_REQUIRED`。
   - 认领复用现有账号操作状态机：幂等键、每人一项未完成操作、每个登录名一项未完成操作、租约、崩溃恢复、待核对与审计。
   - `staff_id`、业务 `subject`、身份链接、角色和团队都不变；姓名只经 SECURITY DEFINER 函数 `claim_own_profile` 写入，并留下不可变的 `profile_audit` 记录。
2. **正式初始化工具** `deploy/baobei/golive-init.py`：一次性使用，只限运维在宿主机运行，没有任何网络接口。见 58 号。
3. **账号服务内部网络**（`b4d6baf`/`056acfd` 已发布）：账号服务通过专用网络 `u-dao-baobei-kc-admin` 访问 Keycloak 管理接口，公网 `/admin/` 继续拒绝。
4. **Web 运行镜像**：`nginx:1.30.6-alpine3.24@sha256:901e593c…7d0a`，并做同系列 `apk upgrade`；构建时检查 `libxslt>=1.1.43-r4`、`zlib>=1.4-r0`，未达到最低版本则构建失败。

## 3. 数据库

- 迁移 00001–00016。00001–00015 未修改；00016 只增加列、约束、索引和一个函数，不新建表。
- 现有正式手机号用户（包括 OWNER）的 `claim_state` 为 `NONE`，不受影响。
- 本次属于不兼容迁移（数据库契约变化），按 direct-deploy 的 `upgrade` 维护窗口执行：维护开始 → 新鲜备份 → 停旧 API → 迁移 → 启动新 API/Web → 冒烟 → 完成。身份纪元不变，**不需要** identity-switch。

## 4. 回退

- **应用回退**：00016 只是增量迁移，旧 API（00015）在新 Schema 上会被迁移清单检查拒绝启动，所以不能用普通 rollback 跨契约回退。如需回到 `056acfd`，走 direct-deploy 的 `disaster-recovery` 窗口，恢复升级前备份（60 号 §4）。
- **初始化回退**：`golive-init.py rollback` 用一次重命名事务恢复初始化前的数据库（58 号 §6）。

## 5. 已知限制与例外

- **SEC-EX-001**：picomatch 开发依赖的限时例外，有效期至 2026-12-18（54 号）。
- **Keycloak 接入专用网络**：这是运行时 `docker network connect`。Keycloak 容器重建后会丢失，下次 Baobei 部署会被发布工具拒绝。长期修复需要另行授权修改 Crane compose（60 号 §6）。
