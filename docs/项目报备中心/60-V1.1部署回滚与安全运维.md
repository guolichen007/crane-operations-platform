# 60 · Baobei V1.1 部署、回滚与安全运维

本文是投产后的运维手册。发布工具的完整契约见 [直接部署与回滚](直接部署与回滚.md) 和 45 号、53 号；身份契约见 [Keycloak生产配置契约](Keycloak生产配置契约.md)。

## 1. 拓扑（生产）

| 组件 | 说明 |
|---|---|
| 共享入口 | 宿主上现有的 Nginx 1.30.4（`nginx:1.30.4-alpine@sha256:dc5069ad…104c`），负责 80/443 和 TLS；`baobei.youdaozd.com` 经 `u-dao-baobei-frontend` 转发到 `baobei-web:8080`。不随 Baobei 升级 |
| baobei-web | `nginx:1.30.7-alpine3.24@sha256:bef15473…8598`，构建时做 `apk upgrade`，以只读方式运行；限流与 CSP 由 `nginx.production.conf` 配置 |
| baobei-api | Go 静态二进制，运行时用户 10001，以只读方式运行。所在网络：`u-dao-baobei-internal`（internal，含 PG）、`u-dao-baobei-egress`（OIDC 发现）、`u-dao-baobei-kc-admin`（internal，成员仅 API 和 Keycloak 别名 `baobei-kc-admin`） |
| baobei-postgres | `postgres:18.4-alpine@sha256:9a8afca5…de15`，只在 `u-dao-baobei-internal` 上；四个应用角色均为最小权限 |
| Keycloak | Crane 的 `u-dao-crane-ops-keycloak-1`，Realm `baobei`。公网只开放 `/realms/` 和 `/resources/`，`/admin/` 一律拒绝 |

**禁止**：

- Baobei API 不得接入 `u-dao-crane-ops_backend`（里面有 Crane PG）或 `u-dao-crane-frontend`（在 Keycloak 信任代理头的网段内）。
- 不得开放公网 `/admin/`。

## 2. 发布（direct-deploy）

1. **推送并等 CI**：OWNER 推送后，必须**同一 Run、Attempt 1、8/8** 通过；CI 失败不能靠重跑当作原 SHA 的首次成功。
2. **prepare**：在服务器本地构建，选 Realm baobei，用 Trivy 0.74.0 离线扫描实际镜像，Web 和 API 都必须是 0 CRITICAL、0 HIGH。
3. **契约相同**（Schema 未变）：普通 `up`，失败时普通 `rollback`。
4. **契约不同**（例如 00015 → 00016）：开 `upgrade` 维护窗口。依次为：MAINTENANCE_ENTER → FRESH_BACKUP_VERIFIED（`tests/baobei/backup.mjs`，带恢复校验）→ OLD_API_DRAINED（工具实测）→ migrate → up → SMOKE_TEST → RELEASE_COMPLETE。身份纪元不变，不需要 identity-switch。
5. **上线后核对**：
   - `docker network inspect u-dao-baobei-kc-admin` 中成员只有 API 和 Keycloak；
   - 公网 `/admin/realms/baobei/users` 返回 403；
   - 从 API 容器经 `http://baobei-kc-admin:8080` 取的 Token，其 `iss` 是公网 Issuer；
   - Schema 与身份纪元正确。

## 3. 账号服务

- **客户端权限**：`baobei-account-service` 在 Realm baobei 中只有 realm-management 的 manage-users、view-users、query-users、view-clients、query-clients 五项，再加 baobei-web 的四个业务角色（只用于分配给用户）；在 master 和 crane 中都没有。
- **异常处理**：账号操作出现“处理中”或“待核对”时，由管理员在网页上点“核对账号状态”，不要直接改数据库或 Keycloak。
- **自动恢复**：后台恢复任务会自动接管租约过期的账号操作，处理方式是先读 Keycloak 的真实状态，再完成、撤销或转入待核对。

## 4. 备份与恢复

- **每日备份**：在服务器定时任务里执行 `node tools/task.mjs baobei backup`（`pg_dump -Fc`、REPEATABLE READ 快照、清单含 sha256、ledger 和表计数，文件 0600），并做恢复演练。
- **跨契约回退**：走 direct-deploy 的 `disaster-recovery` 窗口，依次为 backup（验证升级前备份）→ stop → restore（恢复到临时库并核对后，一次事务换名）→ verify → start（旧版本）。失败的新库会被改名保留，并撤销所有访问权。
- **证据目录**：生产证据放在 `/srv/u-dao/ops/baobei-evidence/`（root 750）。不得放在 `/tmp`，不得提交仓库，也不得包含密码、Token、私钥或完整手机号。

## 5. 安全基线

- **依赖审计**：`npm audit` 门禁（SEC-EX-001 只覆盖 picomatch 开发依赖，到期自动失效）、govulncheck、gitleaks（全历史）、Trivy（镜像）。
- **会话**：`__Host-` Cookie，8 小时有效；会话绑定 Issuer 和身份纪元；每次登录都要求输入密码（`prompt=login`）；涉及高级角色的账号操作要求在 5 分钟内重新验证过密码。
- **业务证据不可变**：审批、提交、参与、建项回执、重复裁决、审核路由、姓名审计、客户审计、技术修订与问答都由触发器阻止改写，对 TRUNCATE 也同样拦截。
- **首次认领**：待认领成员不能访问任何业务接口；姓名和手机号只能由本人提交；认领期间管理员不能代填手机号。

## 6. 已知运维事项

1. **Keycloak 接入专用网络是运行时操作**：用的是 `docker network connect --alias baobei-kc-admin u-dao-baobei-kc-admin u-dao-crane-ops-keycloak-1`，Keycloak 容器重建后会丢失。丢失后再部署 Baobei，发布工具会以“成员不合规 / Keycloak=0”拒绝。处理方式：复测 Crane 登录后重新执行这一接入。长期方案需要 OWNER 另行授权修改 Crane compose。
2. **SEC-EX-001** 到期（2026-12-18）前，要么升级 picomatch，要么重新审批。
3. **漏洞库**：Trivy 离线漏洞库每次扫描前都应更新，或在 24 小时内重新下载。
