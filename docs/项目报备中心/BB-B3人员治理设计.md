# BB-B3 人员治理与调用链审查

基线 1abd8b346a3672f3faf1510cea518ab0ef015f36，CI 41779203800 八门通过。

| 既有基础 | 本轮用法 |
| --- | --- |
| Keycloak 签名 ID Token、client role、app_users、app_sessions | 保留双重授权。新邀请先挂起，受控绑定精确 sub 后仍须通过角色及已验证邮箱检查才激活 |
| identity-apply、identityLock | 保留旧身份初始化。已转入治理的账号拒绝旧入口改写。人员写入拿独占锁，报备写入拿共享锁并重验会话、角色和 capability |
| 归属与审计 | 保留创建人、审批及重复裁决。批量逐项 OCC，独立记录待交接和人员审计 |
| ActionButton、Modal、侧栏及移动样式 | 复用异步状态、确认、键盘焦点恢复和侧栏，在窄屏展示人员卡片 |

销售无人员接口权限。主管只读写本组普通销售。总监处理跨团队销售及交接。管理员管理全部人员与团队，人员视图只返回项目计数，不展示客户项目正文。变更高级角色和高级账号状态要求管理员最近一次明确重新认证，所有变更记录原因。移组或调整角色前应先移交未结束项目，已结束项目保留历史团队。

运行时 SQL 连接和人员治理 SQL 连接分开。常驻运行账户只读原身份字段和 capability，另可记录最后登录时间。人员连接仅具有指定表和列权限，不能更新项目正文、创建人、审批或重复裁决，不能改数据库结构。人员路由从服务端会话获取 actor 并在事务内重验。人员连接在企业登录成功后原子签发 staff_sessions 证明。普通业务 SQL 无权签发或读取该证明，仅伪造 app_sessions 不足以调用人员接口。整个 API 进程失陷或人员凭据被盗不在此边界内，部署应分开保管凭据并审计访问。最后一名有效管理员由数据库触发器保护。

共享 Realm 的最小自动开户权限尚待 Keycloak 26.8.x 隔离验收。BB-B3 交付持久 Outbox 和 root-only、精确 sub 的受控处理。管理员在批准的 Keycloak 操作中核对用户归属与专属 client role，提交本地审批清单，用户随后用已验证邮箱和匹配角色的签名令牌激活。停用立即关闭 Baobei 本地权限并撤销会话，Keycloak 操作保留人工待办。失败可记录并重试。作业无 Keycloak 管理密钥及写入连接，因此没有自动创建、修改或删除共享 Realm 用户的能力。
