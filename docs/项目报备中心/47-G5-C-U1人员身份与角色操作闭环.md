| 步骤 | 实测 |
| --- | --- |
| 已有销售（共享 Realm 历史 subject，ACTIVE，未核验）直接晋升 | 409 STAFF_IDENTITY_NOT_VERIFIED |
| 重新核验 PATCH verifyIdentity → 200 | 仅进入 PENDING_PROVISION，identityVerified=false |
| 在独立 Realm 开通登录账号 | READY；本人登录被拒 LOGIN_NOT_PROVISIONED（状态不变） |
| sync-role（销售，无需重新验证密码） | 精确单一角色 baobei_sales → PENDING_ACTIVATION；同 Key 重放 Replayed |
| 本人登录（含强制改密） | ACTIVE，identityVerified=true，会话角色 sales |
| 晋升主管：无近期密码验证 | 403 STAFF_REAUTH_REQUIRED |
| 晋升主管：有近期验证 → 200 | PENDING_PROVISION；旧销售会话 401；Keycloak 角色仍为 sales；本人登录被拒 |
| 主管 sync-role：无近期验证 | 403，Keycloak 角色未变 |
| 主管 sync-role：有近期验证 | Keycloak 精确 baobei_manager → PENDING_ACTIVATION |
| Keycloak 改成错误角色（director）后登录 | 被拒 LOGIN_ROLE_MISSING，状态不变 |
| 主管本人重新登录 | ACTIVE manager，identityVerified=true；旧销售会话访问业务 401 |

结论：后端闭环可用，**不需要后端修复**，没有伪造 staff.activate、直接改 active 或放宽 identityVerified。问题只在前端：独立 Realm 模式下没有 sync-role 入口，提交 200 后停在“待开通”，而且没有下一步说明。

## 2. B：最小前端改动

- `staff-account.ts` 新增 `account-sync` → `POST …/account/sync-role`，以及 `awaitsRoleSync(m)`：PENDING_PROVISION、账号 READY、已绑定登录身份、没有进行中或待核对的账号操作。
- 成员详情（只有管理员、只有独立 Realm 才显示）：满足上述条件时显示主按钮“同步登录角色”（`staff.account-sync-role`）。沿用账号操作弹窗：每次打开弹窗生成一个 Idempotency-Key，网络失败或超时后用同一 Key 重试；高级角色沿用“验证密码并继续”和草稿恢复（草稿动作新增 `account-sync`），服务端 needsApproval 仍是唯一判定；失败时弹窗内提示，表单保留。
- 状态区分：列表和详情的 `statusLabel` 与 `nextStep` 新增两种状态。“待身份处理”是已提交、登录角色未同步；“待本人重新登录”是已同步、等本人登录。详情页显示四步进度：已提交 → 待身份处理（同步登录角色）→ 待本人重新登录 → 正式生效。提交晋升/降级/核验后的 Toast 改为“已提交，尚未生效：下一步‘同步登录角色’，成员本人重新登录后生效”，不再暗示 HTTP 200 等于已生效。
- 点击 verifyIdentity 或晋升时**不会**自动同步或批准；同步必须由管理员另行点击。
- 交互动作矩阵新增 `staff.account-sync-role`（动作绑定 150）。
