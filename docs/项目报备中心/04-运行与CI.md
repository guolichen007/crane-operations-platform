# 运行与 CI

验证统一入口 node tools/task.mjs baobei <task>，隔离分派 tests/baobei/task.mjs。Go 可通过 BAOBEI_GO 指定既有工具，GOCACHE/GOMODCACHE 可自定义，不改根 engines。
独立前端依赖：npm ci --prefix apps/project-intake-web；独立 Go：cd services/project-intake-api && go mod download。
先 contract / lint / test / build，后 compose / integration / e2e。local-private/baobei/ 保存测试运行配置和截图，不入库。
本地 Compose：node tools/task.mjs baobei up；仅 127.0.0.1:5188 web，Postgres 127.0.0.1:55439；不改现有服务。此 Compose 专用于 synthetic 开发，不能当作生产配置。
本地原生 API：APP_ENV=development DEV_AUTH=1 DATABASE_URL=<本地独立库> LISTEN_ADDR=127.0.0.1:8088 PUBLIC_ORIGIN=http://127.0.0.1:5188 go run .；Vite proxy 默认 8088。
生产配置只定义结构：APP_ENV=production，PUBLIC_ORIGIN=https://baobei.youdaozd.com，OIDC_ISSUER、OIDC_CLIENT_ID=baobei-web、OIDC_CLIENT_SECRET 从外部 secret 提供；redirect 固定 /auth/callback。必须人工预置 app_users/team 和真实 Keycloak client，本轮不执行。没有生产启动 timer。

专用 workflow 仅 push product/baobei-* 或该分支手动 dispatch，禁止在 R2/main 运行。gates：contract、web-quality、api-test、db-test、e2e（desktop + 390x844）、security、compose、build。使用独立 PostgreSQL 16 服务，跑 migration/trgm/API/事务并发；OIDC 以本地 synthetic issuer 测试，真实企业环境 NOT_RUN。
不修改 R2 workflow，不触发生产部署。API 预留审批/转移端点返回 501 NOT_IMPLEMENTED，无按钮假装业务完成。所有已交付动作见交互矩阵。
