# 数据流与故障传播

A：Mock 读数 → Edge Message → MQTT TLS → Cloud 校验 topic/payload 身份与顺序 → PostgreSQL 事务 → 内存 Shadow → REST/WS。内存只在事务成功后更新。
B：告警进入有容量上限的本地关键事件队列，不受 SILENT 限制；QoS 1 发布，Cloud 幂等 message_id 入库后确认。数据库失败时不提前 MQTT 确认，重试形成有界背压。
C：后续点云只走二进制 WebSocket，消费落后丢旧保新；当前无上传。
D：后续远程会话必须先鉴权、RBAC、TTL、设备绑定与审计，再走内部隧道。当前返回未启用。
Broker PUBACK 不等同于应用永久入库确认；Cloud 进程重启的持久消费状态、独立应用 ACK 属 Phase 1 加固。不得宣称端到端 exactly-once。
