# 数据流与故障传播

A：Mock Adapter → 内部 TelemetrySnapshot → Contract Mapper → 类型化 Envelope → MQTT TLS → Cloud 校验 topic/kind/payload、bootSeq/sequence → PostgreSQL 事务 → 内存 Shadow → REST/WS。内存只在事务成功后更新；离线只改 Presence。
B：告警进入容量 256 的本地关键事件队列，不受 SILENT 限制；QoS 1 发布后仍留在 spool。Cloud 按 message_id 幂等提交 PostgreSQL，再发 event/ack；Edge 收到 STORED 后持久删除。数据库失败不发应用 ACK；丢 ACK 后重复发送并再次 ACK。
C：后续点云只走二进制 WebSocket，消费落后丢旧保新；当前无上传。
D：后续远程会话必须先鉴权、RBAC、TTL、设备绑定与审计，再走内部隧道。当前返回未启用。
Broker PUBACK 不等同于应用永久入库确认。T0.5 完成持久 Viewer/Desired State、generation fencing、命令及关键事件应用 ACK；语义为 at-least-once + 幂等消费，不宣称 exactly-once。
