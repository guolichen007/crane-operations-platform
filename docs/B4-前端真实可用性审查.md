# B4 前端真实可用性审查

> 基准：B4-R3 冻结 SHA `cab1c20`。以真实源码为准，逐项给出证据、严重度、最小修复与测试方案。不重新设计整站。

## 1. AssetCenter 名称列显示 `a.id`

- 证据：`apps/web-console/src/views/AssetCenter.vue:135` `<td>{{ a.id }}</td>`；`internal/asset/asset.go` 的 `assetColumns` 与契约 `contracts/go/types.gen.go AssetMasterData` 均未暴露 `display_name`（DB 已有该列，`CreateAsset` 已写入）。
- 严重度：中（名称列对用户不可读，属数据未接线，非业务错误）。
- 最小修复：契约 `AssetMasterData` 增加 `displayName` 字段（`json:"displayName"`）；`assetColumns` 与 `scanAsset` 补 `display_name`；前端名称列改 `{{ a.displayName || a.assetCode || '—' }}`。默认值沿用 `CreateAsset` 的 `assetCode`（空则 `projectId-asset`）。不新增第二套编号。
- 测试：契约 openapi 一致性检查；`go test ./internal/asset`（scan 列对齐）；前端 typecheck + AssetCenter 空/非空断言。

## 2. LocationCenter 项目范围回退首个项目

- 证据：`apps/web-console/src/views/LocationCenter.vue:16-20` `projectId` 在无 `?project=` 时回退 `webSession.projects[0].projectId`，与顶栏「全国运营视图」语义冲突，造成误导性数据范围。
- 严重度：高（数据范围误导，越界风险观感）。
- 最小修复：删除首项目回退；`projectId` 仅取 `route.query.project`，为空时不发请求并显示「请先在顶部选择项目范围」空态（该空态已存在，`LocationCenter.vue:110`）。多项目聚合留待后续，不在本批实现。
- 测试：前端单测（无 `?project=` 时不发 `/locations` 请求、显示空态）；切换项目后缓存键 `['locations', projectId]` 不串数据。

## 3. `/locations` 与 `/catalog` 缺少导航入口

- 证据：`apps/web-console/src/components/SideRail.vue:20-28` `primary` 仅含 数字沙盘/项目组合/项目/资产/运营/告警，无 位置、目录；而 `main.ts:50-51` 已注册 `/locations`、`/catalog` 路由。
- 严重度：低（入口缺失，功能可达性差）。
- 最小修复：在侧栏「资产」下增设次级入口（位置中心、设备目录）或并列两项，不新增一级杂乱菜单；`aria-label="业务导航"` 语义同步。
- 测试：Playwright 断言侧栏出现 位置/目录 入口且可路由到对应页面。

## 4. AssetDetail 位置标签为占位内容

- 证据：`apps/web-console/src/views/AssetDetail.vue:277-279` 位置 tab 仅显示「当前位置与安装历史将在资产位置中心展示…」占位文案。
- 严重度：低（无虚假数据，但未接真实数据）。
- 最小修复：占位文案改为诚实的空态（「暂无安装位置记录」），不接入实际数据；真实安装位置/历史待数据源确定后仅展示实际数据。
- 测试：Playwright 断言位置 tab 显示空态且无占位误导。

## 5. CatalogCenter 写能力边界

- 证据：`apps/web-console/src/views/CatalogCenter.vue` 仅 `listManufacturers`/`listCatalog` 只读展示；后端 `POST/PATCH/...disable` 已存在但未暴露。
- 严重度：低（设计取舍）。
- 最小修复：本批 Catalog 维持只读展示；写能力（制造商/目录新建、编辑、禁用）纳入 R4 管理员工作台，不在本批开放，避免无权限矩阵的前端直接写。
- 测试：后端既有 catalog 写 API 继续由 Go/HTTP 反证覆盖；前端仅验证只读与 GLOBAL 只读标记。

## 6. 资产编辑 409 / DirtyGuard / 空态 / 重试 / 撤销

- 证据：`AssetCenter.vue` 编辑依赖 `updateAsset`，409 仅落到通用 `formError`；无 DirtyGuard、无撤销；`AssetDetail.vue:57-64` `updateMutation.onError` 仅 `e.message`。
- 严重度：中（冲突反馈与误操作保护不足）。
- 最小修复：① 409 时提示「版本冲突，请刷新后重试」（区分 409 与其他错误）；② 编辑弹窗增加「放弃修改」确认（离开未保存时提示）；③ 空态/加载失败/重试沿用现有 `workspace-empty`/`workspace-error` 并补重试按钮。撤销编辑属后续增强。
- 测试：Playwright 断言 409 提示文案；`beforeunload`/路由守卫在脏状态时拦截。

## 7. 服务端分页边界与大数据列表

- 证据：`AssetCenter.vue` 固定 `limit=50`，翻页按 `page*limit`；未展示 `total`，末页判断仅 `length < limit`。
- 严重度：低-中（边界正确但可观测性差）。
- 最小修复：读取并展示服务端 `total`；「下一页」在 `offset+length >= total` 时禁用；列表加载中/失败/空态区分。
- 测试：`go test ./internal/asset`（分页边界）；前端断言 total 展示与末页禁用。

## 8. 全局搜索与资产台账数据源不一致

- 证据：`GlobalSearch.vue:28-50` 搜索 `sceneProvider.devices`/`sceneProvider.projects`（数字沙盘 Inventory 设备），而资产台账来自 `/api/v1/assets`（Asset 主数据）。二者为不同域，同一资产编号在全局搜索与台账可能不一致。
- 严重度：中（跨入口数据口径不一致）。
- 最小修复：本批不合并两域；在全局搜索与台账分别标注数据源口径（沙盘 Inventory vs 资产主数据），避免用户误判；统一口径纳入 R4。
- 测试：文档化 + 搜索框占位文案区分「行车资产（沙盘）」与「资产台账」。

## 9. 1280/1366/1920 对比度、表单空间、弹窗与表格布局

- 证据：`tests/e2e/b4/visual.spec.ts` 已加 1280×720 横向溢出与关键操作可见断言；1366/1920 沿用 premium 检查。文字对比度未系统测。
- 严重度：低（视觉）。
- 最小修复：本批沿用现有 1280/1366/1920 布局回归；对比度专项走后续设计审查，不在本批重做。
- 测试：`playwright --config playwright.b4.config.ts`（1280 布局）；premium 视觉（1366/1920）。
