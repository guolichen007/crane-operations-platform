# B4-R4 交接设计（仅设计，不在 Preview 首轮验收前大范围实施）

> R4 定位：企业级用户、项目权限与操作审计管理中心。Keycloak 负责身份认证，PostgreSQL 负责项目授权与业务审计，不自建密码系统。

## 1. 产品边界

- 用户账号目录与账号状态展示（只读，来源 Keycloak）。
- 项目成员、角色授权与撤销（写，服务端生效 + 留痕）。
- 登录成功 / 失败 / 退出等身份事件的可信来源与查询。
- 资产及 Equipment 操作审计中心。
- 管理员工作台：按用户、项目、时间、业务对象筛选。

## 2. 权限矩阵（复用现有 Capability 体系）

| 能力 | platform_admin | maintainer | operator | viewer |
| --- | --- | --- | --- | --- |
| asset_master_write | ✅ | ❌ | ❌ | ❌ |
| location_write | ✅ | ✅ | ❌ | ❌ |
| catalog_write | ✅ | ✅ | ❌ | ❌ |
| grant_management（R4 新增） | ✅ | ❌ | ❌ | ❌ |
| audit_read（R4 新增） | ✅ | ❌ | ❌ | ❌ |

授权与撤销仅 `platform_admin` 可执行；变更写 `audit_logs`（action `grant_changed` / `grant_revoked`），记录 actor/project/role/request_id。

## 3. API 草案（均服务端鉴权，非前端按钮隐藏）

- `GET /api/v1/admin/users` — 账号目录（Keycloak 同步，只读，分页）。
- `GET /api/v1/projects/{id}/members` — 项目成员与角色。
- `POST /api/v1/projects/{id}/members` / `DELETE /api/v1/projects/{id}/members/{userId}` — 授权/撤销（幂等 + If-Match + 审计）。
- `GET /api/v1/admin/security-events` — 登录成功/失败/退出事件（区分 IdP 事件与应用会话事件）。
- `GET /api/v1/admin/audit` — 操作审计检索（按 actor/project/action/时间/对象，复用 `audit_logs` + `entity_revisions`）。
- 权限变更历史查询，可关联到 `request_id`。

## 4. 页面信息架构（管理员工作台）

- 一级「管理」入口（仅 platform_admin 可见）。
- 用户目录（只读列表 + 账号状态）。
- 项目授权（成员列表、角色下拉、授权/撤销确认弹窗、变更历史）。
- 安全事件（登录失败/成功/退出时间线 + 筛选）。
- 操作审计（资产/Equipment 变更检索，关联 Request ID）。

## 5. 验收测试设计（真实 Keycloak + PG + 浏览器）

- 管理员授权 P001 用户后，用户获得准确 P001 能力；撤销后新请求不能用旧权限。
- 无权限用户不能自行提升；P001/P002 无越权读写。
- 权限变更与资产操作可关联 actor/project/request_id。
- 登录审计区分 IdP 事件与应用会话事件。
- UI 有授权变更确认、失败提示、历史查询。
