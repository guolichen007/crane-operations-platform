# P1 正式使用前：人员、账号与权限管理补齐——实施与验收报告

分支 `feature/crane-r7-sim-e2e`，基线 `424d138`（CI 44243033354 9/9）。源码直部署，不发镜像。Schema 12 → **13**。

## 1. 问题与结论

OWNER 无法登录，也不能在网页上新增登录人员。审查确认：已有 Keycloak OIDC + BFF 会话、项目与项目组合双域 RBAC、项目成员授权；但没有网页人员管理、开户、停用、重置密码、组合角色管理入口，`platform_admin` 只是项目管理员，`tools/identity` 只能在宿主机操作，`provision-keycloak` 不开户。

本专项补齐了一个**独立的系统权限域**和完整的网页人员/账号生命周期，未扩大其他业务功能，未改动 60 分钟容量链路（会话与实时权限链路有改动，已做专项安全回归，见 §4）。

## 2. 设计要点

**权限**：新增系统角色 `system_admin`、`account_manager`（`system_memberships` 表），与 4 个项目角色、2 个组合角色互不推导。系统角色不授予任何项目/组合业务数据访问（HTTP 测试验证系统管理员读 P002 设备仍 404）；`platform_admin` 不获得系统权限。账号管理员只能管理不持有系统角色的普通人员，不能授予任何角色。禁止自我提权/自我降级/自我停用；最后一名启用的系统管理员不能被停用或降级（全局 advisory lock 串行化，含并发互相停用测试）。项目成员仍只由该项目所在组合的经理授予；选择器只对其开放，只返回启用人员的 5 个最小字段，必须带搜索词，最多 20 条。

**Keycloak 集成**：复用 `crane` realm；cloud-api 使用独立机密客户端 `crane-account-service`（client credentials，`fullScopeAllowed=false`），服务账号只有 realm-management 的 `view-users / query-users / manage-users`，并在 scope mapping 中只放这三项；`provision-keycloak` 幂等收敛，多出的角色会被收回。应用侧再加一层：realm 固定且拒绝 `master`，只允许 `/users…` 白名单路径，只操作带 `crane_managed` 属性的用户，拒绝服务账号用户。内部地址 `http://keycloak:8080`，公网 `/admin/` 仍由入口拒绝。cloud-api 不挂载 bootstrap 管理员凭据（契约测试断言）。令牌、临时密码、secret 不入库、不进日志、不进浏览器存储。

**开户状态机**（跨 Keycloak 与 DB 的非原子操作）：

| 状态 | 动作 | 可登录？ |
|---|---|---|
| STARTED | 记录请求（幂等键 + 用户名唯一，不含密码） | 否 |
| IDP_CREATED | Keycloak 创建**停用**用户（带 `crane_user_id`） | 否（Keycloak 停用） |
| BOUND | 一个事务：本地用户（停用）+ 系统/组合授权 + 审计 | 否（两侧都停用） |
| → | 设临时密码（UPDATE_PASSWORD）→ 启用 Keycloak | 否（本地仍停用，BFF 拒绝） |
| COMPLETED | 启用本地用户 | 是，且授权已提交 |

任一步中断后用同一幂等键重试即从记录状态继续；Keycloak 创建响应丢失时按“用户名 + crane_user_id + 停用”认领，不会建第二个账号；外部已存在的同名 Keycloak 用户（非本平台创建）拒绝接管并返回 409；未绑定的开户可放弃（删除停用的 Keycloak 用户，释放用户名）。重复用户名 409。初始密码 16 位、系统随机生成、只在成功响应中出现一次，重放不再返回（需要时重置）。

**生命周期**：停用 = 本地事务（`enabled=false` + 删除全部 web_sessions + 审计）→ 结束实时观看租约（按剩余观看者重算 desired，无人观看则由 Tick 下发 WATCH_STOP）→ Keycloak 停用 + 登出；Keycloak 不可用时平台侧已生效并标记“身份同步待重试”。BFF 每次请求、WebSocket 每帧都重读 `users.enabled` 与会话，所以现有 Cookie 和流立即失效。启用先 Keycloak 后本地，不恢复已撤销的授权。重置密码先撤销会话与实时观看，再设新的一次性密码并登出 Keycloak。所有操作审计 actor、目标、范围、变更摘要、requestId、来源 IP、结果。

**前端**：侧栏「人员与账号」（仅系统角色可见）；列表 + 筛选；新增人员三步；一次性密码对话框（需确认已交付才能关闭）；人员详情（资料、登录账号状态、系统权限、组合授权、项目授权、安全历史）；项目成员授权改为搜索选择；375 移动端适配。

**数据与部署**：00013 前向迁移（Down 拒绝执行）；保留历史账号与 Keycloak 映射，不重建 Keycloak 数据库；reset-business 保留人员、部门、系统角色、开户记录、组合角色、账号审计。部署与首位管理员开通见《docs/08-部署运维与成本/P1-人员账号与权限管理部署与开通手册.md》。

**Gitleaks（security 真实阻断）**：gitleaks v8.30.1 本地扫描完整历史，结果与 CI 一致（353 commits、2 处）：commit `8a28f01`、`tests/e2e/premium/p1-personnel.spec.ts` 第 59、82 行、规则 generic-api-key，内容是 premium 浏览器测试里 `page.route()` **模拟接口**返回的 `temporaryPassword` 字面量。premium 项目不连任何后端，这两个值从未被 Keycloak、数据库或任何账号生成或使用；真实临时密码由 `GeneratePassword` 运行时生成，从不入库、不提交。**分类：SYNTHETIC_TEST_FIXTURE，无需轮换。** `4bb176e` 已替换为明显占位值；按仓库既有规则在 `.gitleaksignore` 中只加入这两个精确指纹（commit:file:rule:line），未关闭 Gitleaks、未忽略目录、未改写远端历史。验证：加入后完整历史无发现；在新提交里再放一个同类合成值仍然报 1 处（反证）。核查已提交证据：`screens/3-one-time-password.png` 显示的是同一个 mock 值（不是真实凭据）；真实 Keycloak 运行记录只含 PASS 行，不含任何密码。B4 真实浏览器用例改为不点「显示」、经「复制」按钮读剪贴板取值，并对该用例关闭 trace/video，CI 附件不会包含真实临时密码。

**integration（R7 恢复演练）**：`TestR7IsolatedRestoreDrill` 硬编码 schema 12。改为 13，并把人员、部门、系统角色、开户记录和审计目标列纳入备份前后指纹。本地真实 Mosquitto + PostgreSQL 跑完整 9 项 SIM-E2E 全部通过（含 20 台 soak 95 s）。

**停用同步重试**：原实现在“本地已停用、Keycloak 失败”后再次停用返回 409，与手册不符。现在 `SetEnabled` 对 `idp_state=PENDING` 的同一目标状态执行幂等重同步（Keycloak 启停用 + 停用时登出 + 再次会话栅栏），成功后变为 SYNCED，之后再重复才是 409；启用同理。每次重试写 `identity_sync` 审计。详情页增加「重试身份同步」按钮。测试覆盖：Keycloak 不可用时停用 → 重复仍 PENDING → 恢复后重试完成（Keycloak 停用、会话清零、DB SYNCED）→ 再重复 409 → 不可用时启用（本地启用但 Keycloak 仍停用，仍不能登录）→ 重试启用。

**账号生命周期竞态**：新增“人员锁”（PostgreSQL 会话级 advisory lock，按 id 排序同时锁操作者与目标，覆盖 Keycloak 调用全程；等待上限 15 s，超时返回 409 `PERSON_BUSY`）。所有账号、角色、开户、纳管操作都在锁内重新读取操作者与目标的角色。确定性反证（假 Keycloak 在指定调用处阻塞，制造真实交叉）：停用进行中启用被拒且最终两侧一致；两位管理员同时重置，后者等待前者完成，Keycloak 中的密码正是后者返回的密码；账号管理员操作期间目标不能获得系统角色；操作者在操作进行中不能被撤权，撤权后其开户/停用/重置/撤销会话全部 403。去掉人员锁的变异体上这 5 项全部失败。

**会话栅栏**：00013 增加 `users.sessions_revoked_at`。停用、重置密码、撤销会话在本地事务里推进栅栏并删除会话，Keycloak 完成后再推进一次（清除期间建立的会话）。BFF 回调在锁定用户行的同一事务内要求 ID Token 的 `auth_time` 严格晚于栅栏，否则拒绝并审计 `authentication_before_session_revocation`。真实 Keycloak 26.8.1 验证：授权码流程的 ID Token 一定带 `auth_time`，复用 SSO 会话时 `auth_time` 不变而 `iat` 变化，所以旧 SSO 会话和栅栏前已发出的回调都会被拒；用户重新输入密码后正常登录。缺少 `auth_time` 视为最早时间（拒绝）。BFF 测试覆盖在途回调、SSO 复用、栅栏后新认证、栅栏时刻认证；去掉检查的变异体失败。

**开户状态机守卫**：未完成开户（STARTED/IDP_CREATED/BOUND）对应的账号不能通过普通启用、重置密码、改系统角色、改组合角色绕过（409 `PROVISION_INCOMPLETE`），BOUND 只能继续不能取消；继续/取消开户在锁内按当前能力复核，授予系统/组合角色的开户只有当前有该能力的系统管理员能继续或取消（账号管理员和被降级的原管理员均 403），完成后审计记录的是实际完成者；继续开户与对该人员的角色修改互斥。

**部署收口**：手册改为真实 `backup.py backup`（`--source-sha` 取当前运行版本）+ `backup.py drill`（随机 `crane_drill_*` 临时库，比对后删除），再 `apply --backup`。`provision-keycloak --account-service-only` 只创建/收敛 `crane-account-service` 并补两个用户属性，不写 realm、`crane-bff`、必需动作、用户与密码，不读 OIDC secret；执行前后对这四类对象取摘要，有变化即失败。真实 Keycloak 上以“预置自定义密码策略 length(12)、会话空闲 1234 s、已有 OWNER 账号”的旧 realm 验证两次执行均 UNCHANGED，随后经账号服务 `adopt-admin` 纳管 OWNER，原密码仍可登录。CI 夹具新增同样的 `--account-service-only` 摘要断言。新增 `TestMigration12To13PreservesPopulatedData`（有数据的 12→13：用户、授权、会话、审计指纹不变，旧身份保持未纳管/启用状态，Down 拒绝）。

## 6b. CI 44333117674（8eb62a1）唯一失败与修复

8/9 成功：repository-contract、backend、r2-db-test、edge、frontend、integration（含 Schema 13 恢复演练与 9 项 SIM）、security（Gitleaks 通过）、a1-security。b4-business-acceptance 在“真实 Keycloak + PostgreSQL 浏览器业务验收”第 86 秒失败，浏览器用例尚未开始，临时密码从未生成。

根因：`provision-keycloak --account-service-only` 的受保护配置摘要误报“crane-bff 已变化”。CI 与服务器上的 Keycloak 使用 PostgreSQL，`crane-bff` 的 `optionalClientScopes` 这类集合字段每次读取返回的顺序不同（本地 dev H2 下顺序稳定，所以本地未复现）。用 PostgreSQL 版 Keycloak 26.8.1 复现：两次连续读取、中间无任何写入，只有 `optionalClientScopes` 顺序不同。这是检测器误报，不是配置被改。

修复：摘要计算前对数组做与顺序无关的规范化（按元素规范化后的 JSON 排序），任何值的增删改仍会被检测到（新增单测覆盖：纯重排不报，改回调地址或删除一个 scope 都报）。没有放宽断言，没有跳过检查。PostgreSQL 版 Keycloak 上完整流程（完整收敛两次 → 仅账号服务三次，每次四项 UNCHANGED）、最小权限 27 项与生命周期 6 项全部通过（证据 `keycloak-26.8.1-postgres-account-service-only.txt`）。
