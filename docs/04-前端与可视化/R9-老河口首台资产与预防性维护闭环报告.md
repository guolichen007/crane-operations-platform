## 2. 关键设计

**人员归档（00014）。** `users` 表新增 `archived_at/by/reason` 和 `protected_reason` 两组字段，并加 CHECK 约束：归档的人员必须是停用状态，受保护身份不能被归档。开户状态新增 `PURGED`，并新建 `purged_usernames` 表，永久删除后用户名不会被重新使用。

- **归档**：只能在 `withPeople` 锁内执行。被保护、本人、最后一名启用的管理员、开户未完成的人员，一律拒绝。执行顺序是先完成本地事务（停用、撤销全部授权、删除会话、写审计），再结束实时观看，最后在 Keycloak 停用并登出。Keycloak 不可用时，本地侧已生效，Keycloak 侧标记为可重试。
- **永久删除**：只允许对已归档的人员执行。删除前用 `to_regclass` 在业务引用表中逐表计数，任何一张表有引用就拒绝（ErrReferenced）。
- **测试账号清理**：只接受 `{reason, accounts:[{id, username}]}` 格式的名单，ID 与用户名必须一致。plan 给出每个账号的处理方式，apply 只执行与已批准 digest 一致的计划。

**Broker。** 新增的 Prometheus 指标是 `mqtt_connected`、`mqtt_connect_failures_total`、`mqtt_down_seconds`，另记录最近一次连接错误的类别。

**首台资产导入（internal/onboarding）。** 暂存清单使用封闭 schema 解析，出现未知字段就拒绝。

- plan 是只读的，会给出 digest 和冲突列表。
- apply 在一个事务里只创建新对象，并写一条 entity_revision 和一条审计记录。
- verify 逐项比对，任何漂移都以退出码 3 报告。
- 同一份清单再次 apply 时结果是 noop；清单内容被改过时，会被识别为 CONFLICT 并拒绝。

原始行以 jsonb 原文保存，并记录行级 SHA256。原文中的 PLC 地址、寿命描述、品牌型号都不改写。

**计量与维护（internal/metering、00015 的 19 张表）。** 设计要点如下：

- **模式隔离**：`meter_states`、`meter_readings`、`maintenance_*` 都带 `source_mode` 字段。规则分真实规则和测试规则（`test_only`）：真实规则只评估 REAL 数据；测试规则只评估该资产实际登记的 SIMULATION / TEST 运行身份（没有登记时按 SIMULATION）。`maintenance_mode_guard` 触发器禁止工单、更换、检查记录跨越 SIM 与 REAL 的边界。
- **规则草案不生效**：导入生成的 53 条规则都是 `DRAFT_UNAPPROVED` 状态，不参与评估，页面上标「待审核（未生效）」。
- **时间规则**：没有遥测数据也会按时间推进。基准日期未知时显示「数据不足」，不会编一个日期。
- **百分比阈值**：用精确值比较，显示时向下取整，所以 79.99% 不会显示成 80%。

**页面。** 资产详情由原来的 2 个标签页扩展为 6 个，只有 maintainer 和 platform_admin 能执行处理操作。维护与到期中心可以按项目、资产、机构、器件、状态、模式筛选。
