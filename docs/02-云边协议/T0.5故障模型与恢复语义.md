# T0.5 故障模型与恢复语义

| 故障 | 检测与恢复 | 自动反证 |
|---|---|---|
| RTC 回拨、新 boot 时间更早 | bootSeq 较高优先，忽略 sentAt 顺序 | shadow 单元测试 |
| 旧 boot SNAPSHOT/LIVE/LWT 延迟 | bootSeq 较低全部拒绝 | shadow 单元测试 |
| 同 boot 旧连接 Will 延迟 | 连接序列区间 fence | mapper 单元测试、真实 TLS Will 测试 |
| 旧 generation STOP 晚到 | STALE，不改变 LIVE | watch 单元测试 |
| 同 commandId 重复/重启再达 | 持久结果去重，不重复执行 | watch 单元测试 |
| broker PUBACK，Edge 没有应用回执 | STARTING，超时 EXPIRED，重新对账 | PostgreSQL repository 与 API 集成 |
| Cloud 重启，Viewer 未过期 | 从数据库恢复 desired，新 generation START | API/Compose 重启集成 |
| Edge 重启/重连 | 保留 bootSeq/fence，BIRTH 触发 Cloud 对账 | watch 与 Compose 集成 |
| Cloud 暂不可用、broker 已 PUBACK | spool 不删除，持续重试原 messageId | 真实 Agent alarm-storm 集成 |
| Cloud 提交成功、event/ack 丢失 | 幂等重发，再次 STORED，再持久删除 | MQTT5/TLS + spool + PostgreSQL 集成 |
| 网络闪断短于 Will Delay | 同 ClientID 恢复会话，取消未发布 Will | 关闭真实 TLS socket 并在 1 秒后重连 |
| 中断超过 Will Delay | OFFLINE + UNEXPECTED，保留业务快照 | TLS socket 与 20 台 SIGKILL 集成 |
| 正常下线 | DEATH + GRACEFUL，尽力发送后正常断开 | 20 台模拟器 SIGTERM 集成 |
| 过期 WATCH 积压 | broker Message Expiry 丢弃，Edge 再校验 deadline | MQTT 离线队列与 watch 单元测试 |
| 浏览器关闭/不续租 | Viewer TTL + grace 后 STOP；Edge TTL 兜底 | 五 Viewer、单 Viewer 过期集成 |
| 本地持久写失败 | 不提前修改队列内存，不能提前确认 | spool 与 atomicfile 单元测试 |

传输语义是至少一次加幂等消费。数据库提交与 MQTT ACK 不做分布式事务；任何一次 ACK 丢失都允许重复。应用 ACK 的含义是 Cloud 已提交数据库，不能代表数据已做异地备份。

Will Delay 从 broker 识别连接断开后计算；静默黑洞还需要 Keep Alive 检测时间。进程连接重试带退避，实际网络恢复超过配置延迟时允许先 OFFLINE 再恢复。短断测试明确关闭 socket，验证 broker 已识别断开后的延迟语义。

Generation 与 bootSeq 依赖持久目录和数据库不被人为回滚。Edge 丢盘、同一 deviceId 多写者、数据库恢复到旧代次等需要人工核对身份和代次，不属于本轮自动容灾承诺。关键队列容量固定 256，满时必须处理告警，不能通过扩大或覆盖队列掩盖容量不足。

验证入口 node tools/task.mjs integration-test；它运行隔离真实 PostgreSQL 测试、真实 MQTT5/TLS 故障、20 台模拟器和浏览器。外部依赖测试在普通 go test 中明确跳过，由 Compose 入口实际执行；不能将跳过当作通过。Linux CI 同时执行 Go race 和完整安全门禁。
